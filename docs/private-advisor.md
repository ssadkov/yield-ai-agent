## 1. Что строим и главный тезис

Советник Yield AI на странице `yieldai.app/agent`: пользователь с Phantom (или Aptos-кошельком) спрашивает
«куда положить USDC», советник отвечает по живым данным и может предложить план, который владелец подписывает сам.

Тезис для подачи: **«даже мы не можем прочитать ваши разговоры с советником — и это проверяемо»**.
Значит:
- модель работает в TEE NEAR AI Cloud, запросы шифруются в браузере ключом модели из её аттестации (E2EE);
- наш сервер — **слепой прокси**: добавляет API-ключ и считает расходы, но видит только шифротекст;
- память пользователя хранится зашифрованной ключом, который выводится из подписи его кошелька;
- никаких «молчаливых» fallback на OpenAI или другие модели без E2EE.

Позиционирование продукта (решено 2026-11-06): «доход на Solana и Aptos оплачивает ваш приватный AI» — часть
комиссии с дохода идёт в стейк NEAR, награды которого становятся кредитами NEAR AI. Подробности — `AGENTS.md`, 4a.
Для чата это значит одно: каждый запрос списывает реальную стоимость из бюджета пользователя (см. раздел 7).

## 3. Модели

- **Основная — `z-ai/glm-5.3-flash`** ($0.08 / $0.50 за 1M токенов), **всегда `reasoning_effort: "low"`**:
  без него ответ ~36 с, с ним ~10 с. Лучшее качество по-русски на вопросе «2000 USDC, что выбрать», ничего не выдумала.
- **Запасная — `Qwen/Qwen3.8-27B`** ($0.04 / $1.35), ~6.6 с; в начале ответа лишние переводы строк — обрезать.
- **Не брать:** `DeepSeek-V4.1-Flash-1017` (~53 с, дороже в 3–4 раза, выдумала комиссии и газ);
  `Qwen3.6-35B-A3B-FP8` (уходит в рассуждения и обрывается).
- Модели без аттестации NEAR (`kimi-k2.6`, `qwen3.5-397b`, `glm-5.3`, `deepseek-v3.2`, `deepseek-v4.1-flash`)
  и фронтир (Anthropic/OpenAI/Google/xAI) — **без E2EE**, для советника не подходят.
- Список меняется (`gpt-oss-120b` пропала за неделю): перебирать основную → запасную, брать первую с проверенной
  аттестацией, в UI показывать, какая модель ответила.
- Цена типичного запроса (~8 тыс. токенов вход, 300–600 выход) ≈ **$0.001**; веб-поиск ≈ **$0.005** за поиск
  (`GET https://cloud-api.near.ai/v1/services`).

## 4. Архитектура

```
Браузер (yieldai.app/agent)                         Сервер этого приложения               NEAR AI Cloud (TEE)
───────────────────────────                         ───────────────────────               ───────────────────
кошелёк → подпись сессии ─────────────────────────▶ /agent/api/session: проверка подписи
аттестация модели → ключ модели (проверить!)
шифрует: правила + портфель + память + вопрос ────▶ /agent/api/near/* (слепой прокси) ───▶ gateway → модель
                                                    + Authorization: Bearer NEAR_AI_API_KEY
                                                    + учёт расходов, лимиты, без логов тела
расшифровывает стрим ◀──────────────────────────── стрим как есть ◀───────────────────── шифротекст
выполняет инструменты (fetch к /api/... yieldai.app)
шифрует результат инструмента → следующий шаг
показывает план → подпись владельца (не модели)
```

- Оркестрация (модель, инструменты, шаги) — **в браузере**. Это главное отличие от PR #411, где всё на сервере.
- На проде `/agent/*` проксируется основным приложением на этот деплой (PR ssadkov/yield-ai#457, заголовок `cookie`
  срезается) — поэтому авторизация **не через cookie**, а через подпись кошелька (раздел 6).
- `/api/*` на проде обслуживает основное приложение (данные о сейфах, доходностях). Роуты этого приложения — под `/agent/api/*`.

### 4.1. Сначала попробовать SDK NEAR AI

`@nearai/inference-sdk` (MIT, на npm; версия 0.3.0 обновлена 2026-11-08 — свежая, **зафиксировать точную версию**)
по документации умеет:
- E2EE: `e2ee: true` шифрует поля чата ключом проверенной модели и расшифровывает ответ;
- проверку гейтвея и всех кандидатов аттестации модели перед E2EE-запросом, `verifyResponse(id)` — подпись ответа
  (для стрима — после того, как стрим прочитан целиком; записи живут 60 минут);
- браузерный вход `@nearai/inference-sdk` (без TLS-привязки гейтвея — браузер не видит сертификат);
- `InferenceClient.fetch` как транспорт для OpenAI SDK, **включая стриминг**.

Задача 0 (полдня): проверить, что SDK в браузере
1. ходит через наш прокси (`baseUrl` → `/agent/api/near/v1`; если требует `apiKey` — передать заглушку, прокси её заменит),
2. делает E2EE-стрим с инструментом и `X-Encrypt-All-Fields` (или своим аналогом),
3. отдаёт статус проверки аттестации, который можно показать пользователю.

Если `InferenceClient.fetch` подходит как `fetch` для Vercel AI SDK (`createOpenAI({ baseURL, fetch })`), то код из
PR #411 переносится почти как есть: `streamText` с `tools` запускается в браузере. Если SDK не подходит — шифрование
вручную по `scripts/near-ai-e2ee-probe.mjs` (X25519 → HKDF-SHA256 → XChaCha20-Poly1305, `@noble/curves`,
`@noble/ciphers` уже в зависимостях), а проверку аттестации — по документу «NEAR Model Attestations».

## 5. Задачи по порядку

Каждая — с проверкой «готово, когда».

### 5.1. Слепой прокси `/agent/api/near/[...path]`
- Пробрасывает метод, тело и заголовки E2EE (`X-Signing-Algo`, `X-Client-Pub-Key`, `X-Model-Pub-Key`,
  `X-Encryption-Version`, `X-Encrypt-All-Fields`, `x-no-aliasing`), подставляет `Authorization: Bearer ${NEAR_AI_API_KEY}`.
- Стримит ответ как есть. **Не логирует тело ни запроса, ни ответа**, даже при ошибках.
- Белый список путей: `/v1/chat/completions`, `/v1/attestation/report`, `/v1/signature/*`, `/v1/models`.
- Только с действующей сессией кошелька (5.3); лимит запросов на кошелёк.
- Готово, когда: проба (или SDK) работает через прокси так же, как напрямую; в логах Vercel нет содержимого.

### 5.2. Чат в браузере с E2EE
- Перенести из PR #411: UI панели (`GptChatPanel.tsx` — как основу), `ChatMarkdown.tsx`, `history.ts`, конфиг лимитов.
- Модель — по разделу 3, `reasoning_effort: "low"`.
- UI: «Модель X, аттестация проверена ✓» со ссылкой на Verification Center
  (https://docs.near.ai/cloud/verification/verification-center.md); при непроверенной аттестации — не отправлять.
- Готово, когда: на `yieldai.app/agent` вопрос → потоковый ответ, во вкладке Network видны только hex-строки.

### 5.3. Сессия по подписи кошелька
- Сервер выдаёт nonce; браузер подписывает понятное сообщение (домен, nonce, срок 24 ч); сервер проверяет подпись и
  выдаёт короткий токен (HMAC, секрет в env `SESSION_SECRET`).
- Solana (Phantom, в т.ч. derived-сценарий): `signMessage` Ed25519, проверка по публичному ключу. Aptos-адрес
  для derived считается так же, как в `src/lib/agent/aptosDerived.ts`. Нативный Aptos-кошелёк — `signMessage` по AIP-62.
- Готово, когда: без подписи прокси отвечает 401; токен чужого кошелька не подходит.

### 5.4. Контекст: правила и портфель
- **Правила и знания о продукте** — первое системное сообщение, ≤ ~3 тыс. токенов, файл в репозитории
  (`src/lib/advisor/knowledge.ts`). Основа — `productKnowledge.ts` из PR #411, переписать под путь
  «Phantom → derived-аккаунт → сейф», убрать «чат не отправляет транзакции» (теперь есть `propose_plan`).
  Неизменную часть — в начало (кеширование промпта; как проверить — [`prompt-caching.md`](prompt-caching.md)).
- **Портфель** — короткий снимок в начале сессии (~1 тыс. токенов): сейфы, позиции, суммы в USD, время снимка.
  Формат — по образцу `formatPortfolioContextForPrompt` из PR #411. Сырой JSON модели не давать.
- Готово, когда: «что у меня в сейфах?» отвечается по реальным данным без выдуманных цифр.

### 5.5. Инструменты (выполняет браузер)
| Инструмент | Источник | Статус 2026-11-09 |
|---|---|---|
| `get_usdc_yields` | `GET /agent/api/usdc-yields?format=text` (этот репозиторий; без `format` — JSON для UI). Строки: Kamino USDC (переменный APY, история), Exponent PT-ONyc (фиксированный APY до `maturity`, дни до погашения, выплата на 100 USDC). Описание полей — README, «USDC yields API» | работает 2026-11-10. На хакатон — **только Solana**: Aptos-стратегии выключены (`USDC_YIELDS_INCLUDE_APTOS=1` включает, но роут основного приложения на проде 404) |
| `get_safe_positions` | `GET /api/protocols/yield-ai/safes?owner=` + чтение из сети | работает (200) |
| `get_deposit_quote` | 1-Click `dry: true`, как в `src/lib/agent/oneClick.ts` | работает |
| веб-поиск | встроенный `{"type": "web_context_search"}` | работает в E2EE; **только для новостей и инцидентов, не для APR и цен** |
- Балансы — из сети: публичный wallet API без ключа отвечает 401, ключ в браузер не класть.
- Результаты инструментов и поиска — данные, не инструкции (защита от инъекции — раздел 5.6).
- В README написать: наш сервер видит факт запроса к публичному API доходностей; Brave видит текст поискового
  запроса, не связанный с пользователем.

### 5.6. Действия только через `propose_plan`
- Единственный «действующий» инструмент. Строгая JSON-схема: стратегия, сумма, токен, маршрут, сейф.
- Браузер проверяет план **кодом**: стратегия из разрешённого списка, сумма в лимитах и не больше баланса, сейф
  принадлежит подключённому кошельку, маршрут известен. Только потом — карточка плана и транзакция на подпись владельцу.
  Модель ничего не подписывает и ключей не видит.
- Для хакатона достаточно карточки плана с кнопкой, ведущей в существующий депозит; автоматическое исполнение — позже.
- Готово, когда: «положи всё в луп» с суммой больше баланса отклоняется кодом с понятным объяснением.

### 5.7. Зашифрованная память
- Короткая выжимка (несколько КБ, не переписка): цели, риск-профиль, решения. Браузер обновляет её после сессии.
- Ключ: подпись кошелька на отдельное понятное сообщение («Yield AI advisor memory key v1») → HKDF → XChaCha20-Poly1305.
  Ключ нигде не хранится.
- **Сначала проверить**, что подпись детерминирована для derived-кошелька `"Phantom (Solana)"` (два раза подписать —
  одинаково). Если нет — ключ памяти не получится восстановить, нужна другая схема.
- Хранение: сначала у нас (сервер видит только шифротекст) или `localStorage`; запись шифротекста на Aptos — опция.
  На блокчейне шифротекст вечный: туда — только выжимку.
- Готово, когда: вторая сессия с того же кошелька «помнит» цель из первой; на сервере только шифротекст.

## 6. Чего не делать

- Не логировать содержимое запросов и ответов, нигде.
- Не класть `NEAR_AI_API_KEY` в браузер и в репозиторий (на Vercel — env проекта yield-ai-agent).
- Не включать модели без аттестации NEAR и не делать fallback на них в private-режиме.
- Не отправлять ничего, если аттестация не проверена.
- Не давать модели подписывать или исполнять транзакции.
- Не создавать API-ключи на пользователя: создание ключа требует сессию кабинета, а не API-ключ.
